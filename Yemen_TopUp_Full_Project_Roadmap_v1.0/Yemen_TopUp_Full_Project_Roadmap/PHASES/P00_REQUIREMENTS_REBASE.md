## الهدف والنطاق
توثيق ما هو موجود فعليًا وتحديد الفجوات على متطلبات المالك السبعة قبل تنفيذ المرحلة الثالثة.

## الأعمال المطلوبة بالتسلسل
1. فحص هيكل المستودع الحالي `apps/backend`, `web-customer`, `web-admin` ومهاجرات Prisma وملفات docs وSwagger، ثم مطابقة التقارير بالوظائف القابلة للتشغيل.
2. تصنيف كل وحدة: موجود ومختبر / موجود ناقص / وهمي أو mock / غير موجود / يعتمد على مزود خارجي، مع أدلة واضحة.
3. تحديد الأنظمة الموجودة للإيداعات ومصدر الحسابات المالية؛ راجع صحة قيد الزيادة والخصم ومطابقة Projection إن وجد.
4. إنشاء قائمة مخاطر لأرقام قنوات الإيداع التي أبلغ عنها المشروع، وعدم استعمال رقم استقبال إنتاجي قبل إثبات ملكيته.
5. معرفة مدى توفر APIs مزودي الشحن والدفع ورقم الهاتف/Player ID وشروط ربط حساب خارجي.
6. إقرار نموذج الشركة التجاري: بيع خدمة رقمية أم إصدار نقود إلكترونية؛ وحسم المسؤوليات القانونية والمالية قبل التشغيل.
7. تحديث `docs/SRS.md` وخريطة المكونات وخطة DB migration دون حذف البيانات السابقة.
8. إعداد Backlog مرقم وتقدير تقريبي للموارد والمراحل مع تحديد Owner لكل بند.

## بوابة الإغلاق (Definition of Done)
