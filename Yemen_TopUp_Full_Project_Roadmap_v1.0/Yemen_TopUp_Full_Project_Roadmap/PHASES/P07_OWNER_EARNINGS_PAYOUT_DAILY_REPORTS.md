## الهدف والنطاق
إظهار الربح المقدّر والمحقق، وطلب سحب الأرباح المتاحة إلى محفظة/حساب موثوق دون توليد أموال وهمية.

## الأعمال المطلوبة بالتسلسل
1. إنشاء Profit Engine يفصل Gross Sales، Supplier Costs، Channel Fees، Refunds، Tax/Operating Expenses حسب السياسة.
2. عرض Estimated Margin قبل التنفيذ، Realized Earnings بعد نجاح وتحقق التكلفة، Available-for-Distribution بعد التسوية والاحتياطات.
3. تعريف Earnings Account/Owner Entitlement مالي منفصل، والتحويل إلى Owner Wallet كقيد توزيعي مناسب عند اعتماده محاسبيًا.
4. حساب السيولة المتاحة بصورة مستقلة: رصيد نقدي فعلي − التزامات محافظ العملاء − ديون المزودين − احتياطي الاسترجاع/التشغيل.
5. لوحة تقرير Daily Close حسب اليوم المحلي: عدد الطلبات والحالات والودائع والمبيعات والتكلفة والرسوم والأرباح المقدّرة والمحققة.
6. تخزين Snapshot يومي لا يعاد كتابته صامتًا، مع Adjustments ملحقة وتقارير PDF/CSV إذا أضيفت.
7. إنشاء PayoutBeneficiary مع تحقق ملكية المستفيد وموافقة الإدارة المالية على تغييره، ثم Payout Request مع MFA.
8. تنفيذ موافقة ثانية وفق المبلغ، حالة PENDING/SENT/CONFIRMED/UNKNOWN/FAILED وإثبات البنك أو المحفظة قبل CONFIRMED.
9. منع صرف ربح غير متحقق أو مستخدم أصلاً لتغطية التزامات العملاء؛ لا يصرف نفس الـPayout مرتين.
10. إن توفر Outbound Payments API يمكن الأتمتة، وإلا تبقى حركات السحب اليدوية موثقة لا مزيفة.

## المخرجات التي يجب تسليمها
- Dashboard نهاية اليوم
- Estimated/Realized/Withdrawable Profit
- Owner Earnings Statement
- Payout Request + Approval + Audit
- Daily Close & Reconciliation Report

## بوابة الإغلاق (Definition of Done)
**مطابقة أرباح أيام تجريبية بالدفتر وكشوف المزود، وسحب اختباري موثق مع موافقات.**

يجب إضافة سجل تنفيذ حقيقي يثبت: نتائج Unit/Integration/E2E، مخطط وتغييرات قاعدة البيانات، endpoints وواجهات UI، مراجع القيود المالية عند ارتباطها بالأموال، وتحديث Swagger والوثائق. أي تكامل لا يملك اعتمادًا رسميًا يوضع `BLOCKED_EXTERNAL` دون ادعاء إنجازه.
