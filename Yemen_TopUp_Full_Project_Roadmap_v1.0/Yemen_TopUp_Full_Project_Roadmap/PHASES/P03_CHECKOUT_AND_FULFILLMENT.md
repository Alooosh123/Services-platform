## الهدف والنطاق
تحويل المحفظة والخدمات إلى شراء قابل للتنفيذ لدى المزود؛ مع Manual Mode قبل اكتمال API.

## الأعمال المطلوبة بالتسلسل
1. تطوير صفحات تصنيف/خدمة/باقة/تفاصيل/Checkout وصفحة `/orders` و`/orders/:id` بالعربية RTL ومتصلة بالـBackend.
2. استخدام Dynamic Fields لتعريف Player ID/Phone/Account ID حسب المنتج، مع Regex Server-Side والتحقق من Availability.
3. حساب السعر النهائي فقط على الخادم مع Snapshot للاسم والسعر والتكلفة والعملة والمستفيد والرسوم والـPriceRuleVersion.
4. تنفيذ حجز ذري للرصيد وقيود Ledger، Idempotency للـCheckout، ومنع double spend بالعمليات المتزامنة.
5. فصل حالة الدفع عن حالة تنفيذ الخدمة مع Order State Machine وأحداث OrderEvent.
6. تطوير `ProviderAdapter` و`ProviderExecution` مع واجهات `submit`, `status`, `validate` وفق إمكانيات المزود.
7. تشغيل Manual Fulfillment حقيقي موثق: موظف معتمد، إثبات شحن، مرجع المزود، وتأكيد النجاح/الفشل.
8. إضافة Worker Queue وTransactional Outbox وRetries آمنة وحالات UNKNOWN وMANUAL_REVIEW؛ منع إرسال طلب مكرر.
9. إن كانت مفاتيح الشحن الرسمية متوفرة، ربط مزود واحد عبر Sandbox ثم Production بعد اتفاق رسمي، وإلا لا تدّعي التشغيل الآلي.
10. تسوية التحصيل أو تحرير الحجز عند ثبوت نتيجة التنفيذ؛ الإرجاع بقيد تصحيحي لا تعديل مباشر لرصيد العميل.

## المخرجات التي يجب تسليمها
- واجهات حقيقية Store/Checkout/Orders
- Order/Provider state machine + Events
- Manual Fulfillment واجهة متصلة وموثقة
- Provider Adapter + Outbox + Queue
- تقرير مالية واختبارات E2E

## اختبارات القبول الخاصة بالمرحلة
- [ ] AT-01, AT-02, AT-03, AT-04, AT-05, AT-06, AT-07
- [ ] فشل مزود مثبت يعيد المال بصورة صحيحة؛ timeout لا يحرر الحجز تلقائيًا
- [ ] نجاح طلبي شراء على أموال متاحة مختلفة دون تجاوز الرصيد

## أهم المخاطر والقيود
- استخدام API غير معتمد أو بيع باقة بلا قناة تنفيذ.
- الخصم النهائي قبل إثبات تسليم الخدمة.
- تكرار الشحن بسبب retries.

## بوابة الإغلاق (Definition of Done)
**Checkout حقيقي وتجربة شحن موثقة (يدوية أو API رسمي) + Ledger balanced + لا تكرار.**

يجب إضافة سجل تنفيذ حقيقي يثبت: نتائج Unit/Integration/E2E، مخطط وتغييرات قاعدة البيانات، endpoints وواجهات UI، مراجع القيود المالية عند ارتباطها بالأموال، وتحديث Swagger والوثائق. أي تكامل لا يملك اعتمادًا رسميًا يوضع `BLOCKED_EXTERNAL` دون ادعاء إنجازه.
