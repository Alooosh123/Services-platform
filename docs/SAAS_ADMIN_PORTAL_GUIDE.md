# دليل بوابة إدارة SaaS

## الغرض

تطبيق مستقل لمسؤول المنصة الأعلى لإدارة منظومة المتاجر المشتركة، وليس لوحة إدارة متجر بعينه. الواجهة موجودة في `apps/web-saas` وتعمل محلياً على المنفذ `3002`.

## التشغيل المحلي

من جذر المستودع:

```powershell
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
docker compose -f docker/docker-compose.yml up -d --build
```

ثم افتح:

- بوابة SaaS: http://localhost:3002
- API: http://localhost:4000/api
- Swagger: http://localhost:4000/api/docs

أو شغّلها منفردة بعد تشغيل الـ API:

```bash
npm run dev:saas
```

يقرأ تطبيق الواجهة عنوان API من `NEXT_PUBLIC_API_URL`، والقيمة المحلية في `.env.example` هي `http://localhost:4000/api`. عند النشر خلف نطاقات عامة، يجب تمرير عنوان API العام الصحيح وقت بناء صورة الواجهة؛ لا تستخدم localhost في متصفح العميل خارج جهاز المطور.

## تسجيل الدخول والصلاحيات

1. استخدم حساباً إدارياً حقيقياً مفعلاً بدور `SUPER_ADMIN`.
2. أدخل بيانات الدخول ثم رمز TOTP من تطبيق المصادقة.
3. لا تحتوي البوابة على حسابات تجريبية أو تجاوز دخول Offline.
4. يرفض الخادم العمليات غير المصرح بها حتى لو حاول المستخدم استدعاء API مباشرة.
5. تحتفظ الواجهة برمز الوصول في تخزين المتصفح المحلي؛ لذلك لا تُشغّلها على جهاز مشترك، وسجّل الخروج بعد الانتهاء. تحسين الجلسات إلى HttpOnly Secure cookies موصى به قبل الإطلاق العام.

## الوظائف المتاحة في الواجهة

- **نظرة عامة:** مؤشرات المتاجر والاشتراكات وMRR بالدولار فقط، الفواتير المعلقة، وصحة المحرك.
- **المتاجر:** البحث، إنشاء سجل متجر مع فاتورة أولية، وتغيير حالة المتجر مع سبب تدقيق إلزامي.
- **الاشتراكات:** استعراض الدورة والقيمة والعملة وفترة الاشتراك والحالة.
- **الفواتير:** استعراض الفواتير وتأكيد الدفع بعد إدخال طريقة الدفع والمرجع والتحقق اليدوي من وصول المبلغ.
- **الخطط:** عرض الخطط وتعديل أسعار USD وYER وSAR.

## ضوابط مالية وتشغيلية

- لا يحوّل النظام العملات ضمنياً. MRR والمبالغ المجمعة في مؤشرات SaaS تعرض USD فقط.
- تعديل سعر الخطة لا يغيّر لقطات أسعار الاشتراكات أو الفواتير التاريخية.
- لا تؤكد فاتورة بناءً على صورة أو رسالة غير متحققة؛ يجب مطابقة وصول المبلغ والمرجع من قناة الاستقبال المعتمدة.
- إنشاء سجل المتجر لا يثبت هوية المالك ولا ينشئ بالضرورة حساب مالك موثقاً؛ استخدم إجراء إسناد المالك المنفصل مع مرجع تحقق هوية.
- قنوات الدفع ومزودو الشحن غير المعتمدين يجب أن يبقوا معطلين.
- لا تضع أسرار API أو كلمات المرور في الواجهة أو المستودع.

## ما لم يثبت بعد

هذه الواجهة لا تعني أن النظام أصبح جاهزاً للإنتاج. يجب اجتياز CI وفحص الاعتماديات، واختبار صلاحيات وعزل SaaS مستقلاً، وربط النطاقات وTLS وإدارة الأسرار، ثم إجراء اختبار تشغيلي في بيئة Staging قبل أي إطلاق.
