# دليل بوابات الدفع والتكامل مع المزودين (Integrations Guide)
## منصة الشحن والخدمات الرقمية — سوق اليمن
**الإصدار:** 1.0 | **تاريخ التحديث:** أكتوبر 2026

### 1. تكامل المحافظ وقنوات الدفع المحلية في اليمن

تدعم المنصة 6 قنوات دفع رئيسية تتطابق مع وسائل السداد الأكثر انتشاراً في السوق اليمني:

| رمز القناة | الاسم العربي | الجهة/المشغل وفق المعلومات العامة | ما يمكن تشغيله حالياً | حالة API/Sandbox |
|---|---|---|---|---|
| `JAIB` | محفظة جيب | شركة عهد للخدمات المالية (AHD Financial Services) | مسار يدوي فقط بعد إثبات الترخيص والعقد وحساب الاستقبال | لم أعثر على وثائق تاجر أو Sandbox عامة؛ لا يوجد Adapter إنتاجي |
| `JAWALI` | محفظة جوالي | بنك اليمن والكويت / WeCash بحسب وثائق المشغل | مسار يدوي فقط بعد التحقق التنظيمي والتعاقد | لم أعثر على مواصفات API تاجر أو Sandbox عامة |
| `CASH` | محفظة كاش / Cash Pay | شركة تمكين لأنظمة وخدمات الدفع الإلكتروني بحسب شروط الخدمة الرسمية | لا تُفعّل قبل عقد Cash Pay وحساب التاجر وموافقة المالية | الموقع الرسمي يعلن API للتجار، لكن مواصفات الربط وSandbox تستلزم التواصل مع الفريق الفني؛ لا يجوز تخمينها |
| `ONE_CASH` | ون كاش | شركة YOU للاتصالات | مسار يدوي فقط بعد إثبات الترخيص والتعاقد | لم أعثر على وثائق API تاجر أو Sandbox عامة |
| `EASY` | محفظة إيزي | شركة/منصة Easy Wallet | مسار يدوي فقط بعد إثبات الترخيص والتعاقد | الموقع الرسمي يعرض خيار API، لكن مواصفات المطور وSandbox غير منشورة في الصفحة العامة |
| `WALLET` | المحفظة الداخلية للمنصة | المنصة مباشرة | رصيد داخلي بقيد مزدوج؛ ليست قناة استقبال خارجية | لا ينطبق |

#### آلية التحقق من المدفوعات اليدوية:
1. يختار العميل القناة (مثال: محفظة جيب).
2. يعرض النظام بيانات الحساب ورقم المحفظة المعتمد للتحويل مع التعليمات باللغة العربية.
3. يقوم العميل بالتحويل وإدخال رقم عملية التحويل (`referenceNumber`) وصورة السند.
4. تظهر العملية في لوحة تحكم الإدارة المالية بحالة `AwaitingVerification`.
5. يقوم موظف المالية بالتحقق من وصول المبلغ إلى كشف حساب محفظة المنصة، ثم يضغط زر "تأكيد واستلام".
6. يقوم النظام فورياً بتسجيل قيد مزدوج في دفتر الأستاذ وإيداع المبلغ في محفظة العميل وإرسال إشعار فوري.

### 2. تكامل مزودي الشحن الرقمي (TopUp Fulfillment Providers)

تعتمد المنصة معمارية المحولات المعيارية (`Adapter Pattern`) عبر واجهة `ITopupProviderAdapter`:

#### 2.1 محول المزود التجريبي الافتراضي (Mock Provider Adapter)
* **الرمز:** `MOCK`
* **الغرض:** محاكاة بيئة الإنتاج بدقة 100% أثناء التطوير أو انقطاع المزودين الخارجيين.
* **الميزات المدعومة:**
  * محاكاة فحص اسم اللاعب (`validatePlayer`): يُرجع اسم حساب افتراضي ومستوى اللاعب.
  * محاكاة النجاح الفوري: إرجاع رقم معاملة وبطاقات الشحن.
  * محاكاة الفشل المدروس: عند إدخال آيدي يبدأ بـ `999`، يحاكي رفض المزود بسبب حظر الحساب لاختبار مسار الاسترجاع المالي التلقائي (`Auto Refund`).
  * محاكاة طوابير الانتظار: عند إدخال آيدي يبدأ بـ `888`، يحاكي حالة `PENDING` لاختبار آليات المزامنة والتحقق اللاحق.

#### 2.2 مزودو الشحن التجاريون المخططون (Roadmap Integrations)
1. **Smile.one API Gateway:**
   * **النوع:** شحن فوري مباشر لشدات ببجي وماسات موبايل ليجندز وجواهر فري فاير.
   * **البروتوكول:** HTTPS POST مع توقيع التشفير `MD5(uid + email + product + time + key)`.
2. **UniPin Electronic Voucher API:**
   * **النوع:** سحب قسائم رقمية وكوبونات شحن الألعاب.
   * **البروتوكول:** RESTful JSON مع توقيع HMAC-SHA256 ومزامنة الأرصدة التلقائية.
3. **مشغل الشحن اليدوي (Manual Fulfillment Operator):**
   * **النوع:** شحن الألعاب والتطبيقات عبر وكلاء محليين يدويًا للحسابات التي تتطلب تسجيل دخول أو شحن مباشر خاص.
   * **الآلية:** تحويل الطلب إلى قائمة انتظار موظفي التنفيذ مع إمكانية إرفاق كود القسيمة وصورة الإثبات وإشعار العميل.
