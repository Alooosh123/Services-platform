# دليل إجراءات التراجع الآمن عن الإصدار (Rollback Procedures Runbook)
## منصة الشحن والخدمات الرقمية — اليمن (Yemen Market Digital TopUp Platform v1.0)
**تاريخ التوثيق:** 11 أكتوبر 2026 | **الإصدار:** v1.0 | **المطابقة:** AR-16 & P10 Requirement 3

---

## 1. أسباب وشروط تفعيل التراجع الآمن (Rollback Triggers)

يتم تفعيل إجراء التراجع الفوري عن الإصدار المنشور عند تحقق أي من الحالات الآتية:
1. فشل فحص الجاهزية بعد النشر (`GET /api/health/ready` يرجع HTTP 503 أو Unhealthy لمدة دقيقتين متتاليتين).
2. ارتفاع معدل أخطاء HTTP 5xx عن **1%** خلال أول 5 دقائق من توجيه حركة المرور للإصدار الجديد.
3. رصد أي اختلال في توازن دفتر الأستاذ العام المزدوج (`Variance > 0.0000`).
4. اكتشاف ثغرة أمنية حرجة أو فشل في بوابة الأسرار بعد النشر.

---

## 2. خطوات التراجع الفني والتشغيلي (Step-by-Step Rollback Execution)

### الخطوة 1: تشغيل سكربت التراجع الآلي
```bash
npx ts-node -r dotenv/config scripts/rollback.ts
```
يقوم السكربت بفحص اتصال قاعدة البيانات، وتأكيد توازن القيود المالية، وتسجيل حدث أمني طارئ في `system_alerts`.

### الخطوة 2: تبديل وسوم الحاويات وإعادة الإصدار السابق (Container Tag Revert)
1. إعادة توجيه حركة المرور في Nginx أو موازن التحميل إلى حاويات الإصدار المستقر السابق (`Version N-1`):
   ```bash
   docker service update --image topup_backend:v1.0.prev topup_backend
   ```
2. التحقق الفوري من استجابة المسار:
   ```bash
   curl -f http://localhost:4000/api/health
   ```

### الخطوة 3: إدارة هجرات قاعدة البيانات (Database Schema Safety)
> [!IMPORTANT]
> **قاعدة ذهبية:** لا يتم حذف أو التراجع الهدام عن أي جداول أو أعمدة محاسبية تم إنشاؤها أثناء الهجرة. تتبع المنصة معيار **Non-Destructive Migrations**:
> - الأعمدة الجديدة تُنشأ كأعمدة اختيارية (`nullable`) أو بقيم افتراضية (`default`).
> - لا يتم حذف أي سجل مالي أو تعديل أي قيد أستاذ عام تم تسجيله أثناء فترة تشغيل الإصدار الجديد.
> - في حال نشوء معاملات مالية خلال الدقائق القليلة للإصدار، تظل محفوظة وتُعالج وفق الإجراءات المحاسبية المعتادة دون أي فقدان للبيانات.

### الخطوة 4: التحقق من استقرار النظام بعد التراجع (Post-Rollback Verification)
1. تشغيل فحص المطابقة الفوري:
   ```bash
   curl -X POST http://localhost:4000/api/monitoring/reconciliation-check -H "Authorization: Bearer $ADMIN_TOKEN"
   ```
2. التأكد من رجوع مقاييس الأداء ومعدل الأخطاء للمستويات الطبيعية (&lt; 0.1%).
3. إشعار فريق العمل والمدير العام بنجاح التراجع الآمن وتوثيق أسباب العطل لتحليل السبب الجذري (RCA).
