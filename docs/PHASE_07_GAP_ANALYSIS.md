## 2. متطلبات اختبارات القبول للمرحلة (Acceptance Tests Mapping)

1. **AT-13: تقرير نهاية اليوم ومطابقة دفتر الأستاذ:**
   - مجاميع الطلبات المنفذة، الإيرادات، التكاليف، رسوم البوابات، والأرباح تطابق دفتر الأستاذ العام المزدوج (`LedgerService`) بالمليم في كل عملة.
2. **AT-14: طلب لم ينفذ بعد (Estimated vs Realized vs Withdrawable):**
   - الطلب في حالة `Processing` أو `Queued` يظهر ضمن `Estimated Profit` ولا يضاف إطلاقاً إلى `Realized Profit` أو `Withdrawable Profit` حتى يتم تنفيذه بنجاح.
3. **AT-17: سحب أرباح المدير والمالك:**
   - طلب سحب لا يتجاوز الرصيد القابل للتوزيع + إدخال رمز TOTP MFA صالح + موافقة الإدارة المالية + إرفاق إشعار التحويل البنكي الخارجي.
4. **AT-18: حماية فشل وتكرار السحب (Idempotency & Hold Release):**
   - محاولة سحب مكررة بنفس الـ Idempotency Key تُرفض ولا تكرر قيد الخصم؛ فشل السحب يفك الحجز فوراً ويعيد الرصيد لمحفظة الأرباح.
5. **AT-23: إصدار التقرير اليومي أكثر من مرة لنفس اليوم:**
   - استدعاء إغلاق اليوم مرة أخرى لا يكرر قيود الأستاذ ولا يغير الـ Snapshot الأصلي، بل يعيد الـ Snapshot المحفوظ مع إلحاق أي تسويات جديدة كـ Adjustments.

## 3. خطة التغييرات البرمجية وقاعدة البيانات

### 3.1 حزمة الأنواع والمشتركات (`packages/shared`):
- إضافة Enums: `DailyCloseStatus`, `OwnerPayoutStatus`, `BeneficiaryVerificationStatus`.
- إضافة DTOs: `CreateDailyCloseDto`, `OwnerPayoutRequestDto`, `ApproveOwnerPayoutDto`, `CreatePayoutBeneficiaryDto`, `LiquidityCheckResult`.

### 3.2 قاعدة البيانات والمخطط (`packages/database/prisma/schema.prisma`):
- نموذج `DailyCloseReport`: Snapshot الإغلاق اليومي للعملات الثلاث (`YER`, `USD`, `SAR`)، عدد الطلبات، الإيرادات، تكلفة المزودين، الهامش التقديري، الهامش المحقق، السيولة، وحالة الإغلاق.
- نموذج `DailyCloseAdjustment`: الفروقات والتسويات اللاحقة الملحقة بالإغلاق اليومي دون تعديل السجل الأساسي.
- نموذج `OwnerEarningsWallet`: محفظة أرباح المالك لكل عملة مع الرصيد الدفتري والرصيد المحجوز والرصيد القابل للتوزيع.
- نموذج `PayoutBeneficiary`: الحسابات البنكية والمحافظ المعتمدة للمالك مع الرقابة الثنائية.
- نموذج `OwnerPayoutTransaction`: سجل حركات سحب الأرباح مع كود الـ MFA والموافقات وسند الحوالة.

### 3.3 الخدمات البرمجية في الخلفية (`apps/backend`):
- إنشاء `ProfitEngineService` داخل `apps/backend/src/modules/reports/`:
  - احتساب `calculateEstimatedVsRealizedProfit`.
  - احتساب `calculateAvailableLiquidity` (النقد الفعلي - التزامات العملاء - مستحقات المزودين - احتياطي الاسترجاع 5%).
- إنشاء `DailyCloseService`:
  - دورة إغلاق اليوم بالتوقيت المحلي لليمن `Asia/Aden`.
  - تخزين الـ Snapshot المالي غير القابل للتعديل.
  - إضافة Adjustments لاحقة لضمان معيار AT-23.
- توسيع `PayoutsService` و `OwnerPayoutsService`:
  - سحب أرباح المالك مع حماية MFA وموافقة الإدارة المالية.
  - إثباتات السداد الخارجي والتحويل لـ `CONFIRMED`.
  - تسجيل قيود التوزيع في دفتر الأستاذ العام المتوازن.
- لوحة تحكم الإدارة (`apps/web-admin`):
  - صفحة تقارير الإغلاق اليومي `/reports`.
  - لوحة أرباح المالك وطلب السحب `/wallets` أو `/earnings`.
