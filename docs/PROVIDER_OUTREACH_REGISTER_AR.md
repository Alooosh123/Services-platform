## 2. مزودو شحن الألعاب

### Smile.One
- وثائق عامة: https://docs.smile.one/
- دعم عبر تذكرة من حساب Smile.One: صفحة FAQ الرسمية https://www.smile.one/eu/message/about/faq
- المطلوب: طلب تأهيل B2B reseller/distributor، تأكيد وجود Wholesale API يمكن لمنصتنا استدعاؤه، حساب Sandbox/UAT، منتجات اختبار، آلية مصادقة وتوقيع، الاستعلام عن حالة الطلب، Webhooks، الرصيد المسبق، الأسعار والخصومات، التسوية والاسترداد، حدود الاستخدام، وProduction approval.
- **تنبيه اتجاه التكامل:** الوثائق المنشورة تشمل Role Check وGame Order وPayment Notification، وتذكر في بعض المسارات أن التاجر يجب أن يستضيف API ليستخدمها Smile.One. لا تفترض أن هذه وثائق API wholesale يمكن لمنصتنا استدعاؤها. يجب أن يؤكد فريق Smile.One نموذج التكامل الصحيح للموزع/المتجر في اليمن.
- لا يوجد بريد B2B API مخصص تم التحقق منه في صفحات الدعم المفتوحة؛ استخدم تذكرة الدعم بحساب تملكه. لا تستخدم نموذج شراكة المؤثرين كأنه نموذج API.

### UniPin
- بوابة المطورين/التسجيل: https://developer.unipin.com/
- وثائق المطورين: https://developer-docs.unipin.com/
- بريد الدعم العام الذي تعرضه صفحة دعم UniPin: `support@unipin.com`
- المطلوب: حساب مطور/شريك من بريد تجاري تملكه، تفعيل برنامج B2B In-Game Top Up API، Sandbox workspace، test merchant/project ID، API specification/OpenAPI/Postman، مفاتيح اختبار، webhook signature، IP allowlist، order status inquiry، idempotency، pricing/commission، funding/settlement، refund، وقائمة المنتجات/الدول/العملات.
- يلزم التسجيل اليدوي والتحقق من البريد وربما KYB/مراجعة شريك قبل إظهار صلاحيات API.

## 3. الحزمة الموحدة التي يجب تقديمها للجهات
1. الاسم القانوني والشكل القانوني وبلد التسجيل والعنوان.
2. السجل التجاري/ترخيص مزاولة النشاط، إن وجد.
3. بيانات المالك والمفوض بالتوقيع وإثبات صلاحية التفويض.
4. حساب تجاري باسم المنشأة لاستلام التسويات.
5. رابط موقع/تطبيق المنصة، وصف النشاط والمنتجات والأسواق المستهدفة.
6. شروط الاستخدام، الخصوصية، سياسة الاسترداد والشكاوى.
7. وصف مكافحة الاحتيال وKYC/AML وحماية البيانات، حسب ما تطلبه الجهة.
8. خطاب طلب حساب تاجر/شريك وبرنامج API/Sandbox.

لا تُرسل المستندات الحساسة إلا عبر قناة رفع آمنة تحددها الجهة بعد التحقق من المستلم.

## 4. مدخلات يدوية لازمة من مالك المشروع
- تعبئة الحقول في حزمة الخطابات: الاسم القانوني، الشكل القانوني، بلد ومكان التسجيل، رقم السجل/الترخيص، العنوان، اسم المفوض وصفته، البريد التجاري والهاتف، رابط الموقع أو التطبيق.
- إنشاء/تأكيد حساب تجاري لدى كل مزود عندما يطلب ذلك.
- إتمام CAPTCHA وOTP وتأكيد البريد/الهاتف وتوقيع الاتفاقيات ورفع مستندات KYB بنفسه.
- إدخال أسرار Sandbox/Production مباشرة في Secret Manager أو بيئة السيرفر، لا في GitHub أو المحادثة.

## 5. شروط الإطلاق
- لا تُرسل أو تُنفذ مدفوعات قبل تأكيد الترخيص/الموافقة التجارية الحالية.
- لا تستخدم محفظة شخصية أو حساباً شخصياً للمنصة دون موافقة مكتوبة تسمح بالاستخدام التجاري.
- لا تطلب PIN/OTP أو كلمات مرور المستخدمين أو الوكلاء، ولا تعتمد على صور الإيصالات وحدها.
- لا يتم شحن لعبة أو إكمال طلب مدفوع إلا بعد تأكيد حقيقي من المزود، مع idempotency وحفظ مرجع المعاملة ومطابقة دفتر الأستاذ.
- أي Timeout مجهول النتيجة ينتقل إلى reconciliation/manual review ولا يعاد الطلب تلقائياً.
