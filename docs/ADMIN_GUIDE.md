### 1. تسجيل الدخول والوصول إلى لوحة التحكم الإدارية

* **رابط لوحة التحكم:** `http://localhost:3001`
* **الحسابات الافتراضية للتشغيل والتجربة:**
  * **المدير العام / مالك المنصة (`OWNER`):**
    * البريد: `admin@digitaltopup.com`
    * كلمة المرور: `Admin@123456`
  * **المدير المالي والعمليات (`FINANCE_MANAGER`):**
    * البريد: `finance@digitaltopup.com`
    * كلمة المرور: `Finance@123456`
  * **حساب عميل تجريبي لاختبار الشراء (`CUSTOMER`):**
    * البريد: `customer@gmail.com`
    * كلمة المرور: `Customer@123456`
    * الأرصدة المودعة مسبقاً: `50,000 ر.ي` | `100.00 $` | `200.00 ر.س`

### 2. إدارة الكتالوج والخدمات الديناميكية (Catalog Management)

#### إضافة خدمة جديدة (مثال: لعبة أو تطبيق شحن جديد):
1. انتقل إلى تبويب **"الخدمات والمنتجات"** في لوحة الإدارة.
2. انقر على **"إضافة خدمة جديدة"**.
3. أدخل البيانات الأساسية:
   * الاسم بالإنجليزية والعربية (مثال: `Free Fire` / `فري فاير`).
   * الرمز اللطيف الفريد (`slug`: `free-fire`).
   * التصنيف (ألعاب موبايل، تطبيقات ترفيه، بطاقات رقمية).
   * أيقونة الخدمة وصورة البانر الإعلاني.
4. **تعريف حقول المستفيد الديناميكية:**
   * أضف حقلاً جديداً (مثال: `معرف اللاعب - Player ID`).
   * اختر نوع الحقل (`text` أو `number` أو `select`).
   * حدد ما إذا كان الحقل إلزامياً (`required = true`).
   * أدخل التعبير النمطي للتحقق (Regex) لمنع أخطاء إدخال اللاعبين (مثال: `^[0-9]{8,12}$`).
5. **إضافة باقات المنتجات والأسعار:**
   * أضف منتجاً (مثال: `100 جوهرة`).
   * حدد سعر التكلفة وسعر البيع بشكل منفصل لكل عملة:
     * الريال اليمني (`YER`): تكلفة 450 / بيع 500
     * الدولار الأمريكي (`USD`): تكلفة 0.90 / بيع 1.00
     * الريال السعودي (`SAR`): تكلفة 3.40 / بيع 3.75
6. احفظ الخدمة؛ ستظهر فوراً في واجهة العملاء دون الحاجة لإعادة تشغيل الخادم.

### 3. العمليات المالية والتدقيق (Financial Operations)

#### أ. تدقيق واعتماد طلبات شحن المحافظ اليدوية:
1. افتح تبويب **"المدفوعات والشحن"** ثم قسم **"طلبات الشحن المعلقة"**.
2. راجع رقم الحوالة وتفاصيل محفظة التحويل (جيب، جوالي، كاش، ون كاش).
3. قارن رقم الحوالة مع كشف حساب المحفظة البنكية الخاص بالمنصة.
4. انقر على **"تأكيد الإيداع"**:
   * يسجل النظام آلياً قيداً محاسبياً مزدوجاً: يرفع حساب وسيط النقدية، ويزيد رصيد التزام محفظة العميل.
   * يصل إشعار للعميل باكتمال الإيداع وظهور الرصيد في محفظته فورياً.

#### ب. إجراء التعديلات والتسويات الإدارية العكسية:
* في حال وقع خطأ أو تطلب الأمر تعويض عميل:
  * انتقل إلى **"دفتر الأستاذ المالي"**.
  * اختر **"تعديل رصيد إداري"**.
  * حدد العميل، العملة، نوع الحركة (`CREDIT` أو `DEBIT`)، والمبلغ.
  * اكتب السبب الإلزامي والمبرر المحاسبي للعملية.
  * يُنشئ النظام قيداً متوازناً ضد حساب التسويات ويسجل العملية في سجل التدقيق المالي.

### 4. إدارة ومتابعة الطلبات والتنفيذ (Order Fulfillment)

* **الطلبات الناجحة:** تظهر باللون الأخضر بحالة `Completed` متضمنة كود العملية أو القسيمة المسلّمة.
* **الطلبات قيد المراجعة اليدوية (`ManualReview`):**
  * تحدث في حال انقطاع اتصال مزود الشحن أو الحاجة للشحن اليدوي.
  * يفتح موظف التنفيذ تفاصيل الطلب، يشحن الحساب عبر المنظومة المعتمدة، ثم يرفق كود العملية أو صورة السند ويضغط **"إكمال التنفيذ"**.
* **الطلبات الفاشلة (`Failed`):**
  * في حال رفض المزود العملية لعدم وجود الآيدي، يُرجع النظام الرصيد فورياً لمحفظة العميل مع توضيح سبب الرفض باللغة العربية.
