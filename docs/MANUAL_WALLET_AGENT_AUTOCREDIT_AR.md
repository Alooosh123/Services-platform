# ربط حسابات المرسل والإيداع الآلي عبر المحافظ اليدوية

## الهدف

يحفظ العميل معرّف حساب الإرسال الخاص به مرة واحدة لكل قناة يدوية (مثل رقم البديل أو رقم الهاتف المرتبط بالمحفظة). عند إنشاء طلب الإيداع، يربط النظام الطلب بالحساب المحفوظ. يستلم وكيل محافظ مخوّل المهمة، ويراجع سجل الحركة الوارد من تطبيق/كشف الحساب الرسمي لحساب الاستقبال، ثم يرسل القيم المرصودة إلى الخادم.

**هذا ليس مسحاً آلياً لحساب المحفظة.** في القنوات التي لا توفر API رسمياً، لا يملك الخادم وسيلة موثوقة للدخول إلى تطبيق المحفظة أو قراءة سجلها. الوكيل هو من يفحص السجل الرسمي؛ وبعد إدخاله بيانات الحركة يستطيع الخادم تنفيذ القيد المزدوج تلقائياً وفق شروط الأمان أدناه.

## حساب المرسل المحفوظ

- نقطة الحفظ: `POST /api/deposits/sender-accounts`
- نقطة العرض: `GET /api/deposits/sender-accounts`
- الحفظ مرتبط بالمستخدم الحالي والقناة الحالية وسياق المتجر.
- مسؤول القناة يحدد نوع المعرّف من `POST /api/admin/deposits/channels/:channel/sender-identifier-type`، ويسجل التغيير في سجل التدقيق.
- تتطلب العملية موافقة صريحة على الحفظ لغرض مطابقة الإيداعات.
- تُشفّر قيمة المعرّف باستخدام AES-256-GCM عبر `ENCRYPTION_KEY`.
- يُنشأ HMAC-SHA256 للبحث ومنع ربط نفس المعرّف بأكثر من عميل في القناة/المتجر.
- لا تعرض واجهة العميل سوى القيمة المقنّعة وآخر أربعة أرقام.
- لا يحصل الوكيل على القيمة الكاملة إلا بعد استلام المهمة، ولا تُعاد لأي وكيل آخر أو للعميل في قائمة الإعدادات.
- تحديث المعرّف يعيده إلى حالة `PENDING_VERIFICATION` حتى ينجح تحقق لاحق.

يدعم إعداد القناة الأنواع التالية عبر `senderIdentifierType`:
- `ALIAS`: رقم البديل/المعرّف البديل، إذا أكد مزود المحفظة رسمياً أن هذا هو المعرّف الظاهر للمرسل.
- `PHONE`: رقم الهاتف المسجل في حساب المحفظة.
- `WALLET_ID`: معرّف المحفظة.
- `ACCOUNT_NUMBER`: رقم الحساب.

الإعداد الافتراضي لجيب في هذه النسخة هو `ALIAS` وفق طلب التشغيل، وبقية المحافظ `PHONE`. يمكن لمسؤول القناة تغيير النوع من لوحة إدارة قنوات الدفع؛ وإذا تبيّن أن جيب أو أي محفظة لا توفر رقماً بديلاً، اختر `PHONE` ليطلب التطبيق رقم الهاتف المرتبط بالمحفظة. يجب أن يعيد العميل حفظ معرّفه عند تغيير النوع.

## رحلة الإيداع

1. يعرض النظام القنوات اليدوية النشطة التي اجتازت التحقق التنظيمي وتحتوي على حساب استقبال واتفاقية مزود.
2. يسجل العميل معرّف حساب الإرسال مرة واحدة. ويمكنه تركه محفوظاً في الطلبات اللاحقة.
3. ينشئ العميل طلباً بالعملة والمبلغ. يجوز ترك المرجع فارغاً للقنوات اليدوية لأن الوكيل سيقرأ المرجع من كشف الحركة.
4. ينشئ الخادم مهمة وكيل مرتبطة بمعرّف العميل وحساب الاستقبال المتوقع وآخر أربعة أرقام من الحسابين.
5. يستلم وكيل محافظ نشط المهمة، ويطالع سجل الحساب المستقبِل الرسمي، ثم يدخل هوية المرسل الكاملة كما ظهرت في الحركة، والمبلغ والعملة والمرجع الفعلي وآخر أربعة أرقام من حساب الاستقبال ومرجع سطر الكشف/الإثبات.
6. يقارن الخادم هوية المرسل الكاملة بعد التطبيع مع المعرّف المحفوظ، ويشترط أيضاً تطابق حساب الاستقبال والمبلغ والعملة والمرجع الفريد ووجود دليل/مرجع كشف، إلى جانب صلاحية القناة ووثائقها.
7. عند تحقق كل الشروط وتفعيل الإعدادات، ينفذ الخادم قيداً مزدوجاً داخل المعاملة نفسها، ويحدّث طلب الإيداع ومهمة الوكيل والحساب المحفوظ وسجل التدقيق. أي فشل يسبب التراجع عن المعاملة كلها.
8. إذا لم تتطابق أي قيمة أو تكرر المرجع أو نقصت الوثائق أو تعطّل MFA أو تجاوز المبلغ السقف، لا يُضاف رصيد وتعود العملية إلى المراجعة المالية.

## بوابة القيد الآلي

الإعدادات الافتراضية في `.env.production.example` تبقي القيد الآلي مغلقاً:

```dotenv
ENABLE_AGENT_AUTO_CREDIT=false
WALLET_AGENT_AUTO_CREDIT_CHANNELS=
WALLET_AGENT_AUTO_CREDIT_MAX_AMOUNT_YER=0
WALLET_AGENT_AUTO_CREDIT_MAX_AMOUNT_USD=0
WALLET_AGENT_AUTO_CREDIT_MAX_AMOUNT_SAR=0
WALLET_AGENT_AUTO_CREDIT_DAILY_MAX_COUNT=0
WALLET_AGENT_AUTO_CREDIT_DAILY_MAX_AMOUNT_YER=0
WALLET_AGENT_AUTO_CREDIT_DAILY_MAX_AMOUNT_USD=0
WALLET_AGENT_AUTO_CREDIT_DAILY_MAX_AMOUNT_SAR=0
```

لا تفعّلها إلا بعد الموافقة التنظيمية والتعاقدية واختبار Staging ومراجعة أمنية. يلزم استيفاء جميع الشروط معاً:
- تفعيل العلم العام، وإضافة رمز القناة صراحةً إلى `WALLET_AGENT_AUTO_CREDIT_CHANNELS`؛ القائمة الفارغة تمنع القيد الآلي.
- تحديد سقف لكل عملية لكل عملة، وسقف يومي لعدد عمليات الوكيل وإجمالي القيمة لكل عملة وفق توقيت UTC. أي حد مفقود أو صفر يمنع القيد الآلي لهذه السياسة.
- تفعيل MFA للوكيل وإدخال رمز TOTP حديث من ستة أرقام لكل عملية مؤهلة؛ لا يكفي أن يكون MFA مفعلاً في الحساب فقط.
- قبول الرمز لمرة واحدة عبر Redis anti-replay. يُرفض الرمز المعاد استخدامه، كما تتوقف محاولة القيد الآلي عند تعذر Redis.
- لا يترحل الرصيد إلا بعد تطابق هوية المرسل الكاملة مع المعرّف المحفوظ، والمبلغ والعملة وحساب الاستقبال والمرجع الخارجي الفريد، مع تحقق عقد القناة ووثائقها.

عند تجاوز سقف عملية أو سقف يومي، أو غياب MFA، تُحال العملية إلى المالية بدلاً من القيد الآلي. أما غياب رمز TOTP أو عدم صحته أو إعادة استخدامه فيوقف محاولة الوكيل دون تعديل الطلب أو إنشاء قيد، حتى يعيد الوكيل المحاولة برمز جديد.

## واجهات وأمان الوكيل

- قائمة مهام الوكيل مقيدة دائماً بسياق المتجر، بما في ذلك طلبات PENDING.
- لا يمكن للعميل أو الوكيل تنفيذ المطابقة لإيداع يخص حسابه الشخصي.
- لا تُظهر هوية المرسل الكاملة إلا للوكيل الذي استلم المهمة وفي حالة `CLAIMED`.
- يمنع تكرار المرجع الخارجي عبر القناة، ويمنع ترحيل الإيداع أكثر من مرة.
- يستخدم القيد دفتر الأستاذ المزدوج ومرجع idempotency المرتبط بطلب الإيداع.
- لا يسجل سجل التدقيق النص الكامل لهوية المرسل؛ يسجل آخر أربعة أرقام ومرجع الحركة والإثبات ونتيجة المطابقة.
- لا يحق للوكيل إنشاء أو تعديل الأرصدة مباشرة.

## قنوات API

قنوات API غير معروضة وغير قابلة للإيداع في هذا الإصدار حتى يكون لها محول خاص بالمزود، وواجهة API رسمية، وحساب Sandbox، واختبارات توقيع/تكرار، وبيانات اعتماد محفوظة في مخزن أسرار مناسب. لا يعني تغيير وضع القناة إلى `API` أن التكامل أصبح جاهزاً؛ فالخادم يرفض Webhooks الإنتاجية حالياً حتى تثبيت محول تاجر معتمد. لا تستخدم محول MANUAL كبديل صامت لقناة API.

لكل مزود API يجب إكمال:
- خطاب/اتفاقية تاجر وتأكيد صلاحية استقبال مدفوعات نشاط المنصة.
- وثائق رسمية للـ API وWebhook، ونموذج التوقيع والطابع الزمني، وسياسة الاستعلام عن الحركة.
- حساب Sandbox ومفاتيح اختبار، ثم اختبارات نجاح/فشل/تكرار/تأخر/نتيجة غير معروفة.
- مفاتيح الإنتاج عبر مخزن أسرار، وقائمة host allowlist، وخطة تدوير مفاتيح.
- اختبار التسوية اليومية وكشف الحساب قبل الإطلاق.

## التراجع والإيقاف

لإيقاف القيد الآلي فوراً:
1. اضبط `ENABLE_AGENT_AUTO_CREDIT=false`.
2. أعد قيم حدود العملات إلى صفر.
3. أوقف قناة الدفع أو استخدم Kill Switch عند الاشتباه بتزوير أو اختلاف في الكشف.
4. لا تحاول إعادة تنفيذ طلب كانت نتيجة المزود فيه غير معروفة؛ أرسله للمطابقة.

## اختبارات الأمن المضافة

- تشفير معرّف المرسل وعدم ظهوره في الاستجابة.
- الموافقة الصريحة والتحقق من نوع المعرّف المسموح للقناة.
- منع إعادة ربط نفس المعرّف بعميل مختلف.
- مطابقة هوية المرسل الكاملة والمبلغ والعملة وحساب الاستقبال.
- منع المراجع الخارجية المكررة.
- منع القيد عندما يكون MFA غير مفعل أو وثائق المزود ناقصة.
- طلب TOTP حديث، والتحقق من صحته، ورفض إعادة استخدام الرمز، مع تحديد معدل المحاولات عبر Redis.
- منع القيد لقناة غير مدرجة في allowlist أو عند بلوغ سقف العملية/السقف اليومي للوكيل.
- إيقاف القيد الآلي عند تعطيل العلم أو غياب Redis أو أي حد من حدود التشغيل.
- التحقق من عزل مهام الوكيل حسب المتجر.
