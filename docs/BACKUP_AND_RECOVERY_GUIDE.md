# دليل النسخ الاحتياطي واستعادة البيانات (Backup & Recovery Guide)
## Digital TopUp & Services Platform

تستخدم هذه الأدوات `pg_dump` و`pg_restore` بصيغة PostgreSQL المخصصة. لا تُصدّر بيانات العملاء إلى JSON، ولا تُسجّل بيانات الاتصال في المخرجات. يلزم تثبيت أدوات PostgreSQL client وإتاحتها في `PATH`. في تثبيت Windows القياسي، أضف مجلد `bin` الخاص بإصدار PostgreSQL إلى `PATH` أو شغّل الأوامر في جلسة أُضيف فيها هذا المجلد.

## إنشاء نسخة احتياطية

اضبط `DATABASE_URL` في ملف `.env` أو بيئة التشغيل، ثم نفّذ من جذر المشروع:

```powershell
npm run db:backup
```

تنشأ نسخة `*.dump` وبجانبها ملف `*.dump.sha256` داخل مجلد `backups` افتراضياً. يمكن تغيير الموقع عبر `BACKUP_DIR`. لا تحذف الأداة النسخ القديمة تلقائياً؛ طبّق سياسة احتفاظ ونسخ خارج الجهاز وفق ضوابط التشغيل، واحمِ ملفات النسخ لأنها تحتوي بيانات كاملة.

## استعادة اختبارية معزولة

أنشئ قاعدة PostgreSQL اختبارية فارغة منفصلة مسبقاً، واضبط `RESTORE_DATABASE_URL` عليها. يجب أن يتضمن اسم القاعدة `restore` أو `test` أو `sandbox`، ولا يجوز أن يكون اسم إنتاج/قاعدة حية. افتراضياً تُقبل أهداف الاستعادة المحلية فقط.

```powershell
$env:RESTORE_DATABASE_URL = "postgresql://user:password@localhost:5432/digital_topup_restore?schema=public"
npm run db:restore -- --file "backups\postgres_<timestamp>.dump" --confirm-restore
```

الاستعادة تنظف الكائنات الموجودة في قاعدة الهدف قبل تحميل النسخة (`--clean`)، لذلك لا تستخدم سوى قاعدة اختبار معزولة. لاستهداف PostgreSQL بعيد، يلزم قرار تشغيلي واعٍ وتعيين `ALLOW_REMOTE_RESTORE=true` مؤقتاً، مع إبقاء شرط قاعدة الاختبار وتأكيد الأمر. تمنع الأداة العمل عند `NODE_ENV=production`، وتتحقق من SHA-256 وصحة أرشيف PostgreSQL قبل بدء الاستعادة.

## حدود التحقق

نجاح النسخ أو الاستعادة وحده لا يثبت اجتياز AT-20. يجب إجراء الاستعادة فعلياً ثم التحقق من قيود دفتر الأستاذ، وقياس RTO/RPO من سجل زمني موثوق، وتوثيق النتائج قبل تغيير حالة P10. لا تنفذ استعادة إلى قاعدة الإنتاج بهذه الأدوات.

تم التحقق محلياً من إنشاء نسخة PostgreSQL مخصصة واستعادتها إلى قاعدة جديدة معزولة في 29 أكتوبر 2026. احتوت النسخة المستعادة على المخطط والترحيلات الخمس؛ كان دفتر الأستاذ فارغاً، لذلك لا يعد هذا التحقق دليلاً على سلامة أرصدة معاملات فعلية أو تحقيق أهداف RTO/RPO.
