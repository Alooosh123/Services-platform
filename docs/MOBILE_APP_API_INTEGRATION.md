# دليل تشغيل تطبيق Flutter وربطه بالـ API

## ما تم ربطه

تطبيق العميل في `apps/mobile-customer` لم يعد يعرض بيانات ثابتة على أنها بيانات حقيقية. تمت إضافة عميل API واستخدام المسارات التالية:

| الوظيفة | المسار |
|---|---|
| تسجيل عميل | `POST /auth/register` |
| تسجيل الدخول | `POST /auth/login` |
| تجديد الجلسة | `POST /auth/refresh` |
| الملف الشخصي | `GET /auth/profile` |
| كتالوج الخدمات | `GET /products/catalog` |
| إنشاء طلب شحن | `POST /orders/checkout` |
| سجل الطلبات | `GET /orders/my-orders` |
| تفاصيل الطلب | `GET /orders/:id` |
| أرصدة المحافظ | `GET /wallet/balances` |
| إعداد PIN مالي | `POST /auth/transaction-pin` |

تُحفظ رموز الجلسة باستخدام `flutter_secure_storage`. ويُرسل رمز المعاملة في ترويسة `x-transaction-pin` عند تنفيذ Checkout. يتم توليد Idempotency Key مرة واحدة لكل شاشة شراء وإعادة استخدامه عند إعادة المحاولة. الأسعار والتحقق من الرصيد والخصم تظل من مسؤولية الخادم.

## إعداد Flutter محلياً

المجلد يحتوي على مصدر Flutter، لكن يلزم إنشاء ملفات المنصات الأصلية إذا لم تكن موجودة. من PowerShell:

```powershell
cd apps/mobile-customer
flutter create --platforms=android,ios .
flutter pub get
flutter analyze
flutter test
```

إذا كان Android Emulator يعمل على نفس جهاز التطوير، عنوان الخادم الافتراضي مضبوط على:

`http://10.0.2.2:4000/api`

شغّل التطبيق:

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:4000/api
```

في جهاز Android فعلي، استبدل `10.0.2.2` بعنوان IP المحلي لجهاز التطوير، وتأكد من اتصال الهاتف والحاسوب بالشبكة نفسها. لا تستخدم `localhost` داخل محاكي Android لأنه يشير إلى المحاكي نفسه.

## إعداد الاتصال المحلي غير المشفر

HTTP مسموح هنا للتطوير المحلي فقط. إذا منع Android الاتصال الصريح، أضف `android:usesCleartextTraffic="true"` إلى وسم `<application>` في `android/app/src/main/AndroidManifest.xml` لنسخة التطوير فقط. لا تستخدم هذا الإعداد في إصدار إنتاجي؛ استخدم HTTPS وشهادة TLS صحيحة.

## تدفق الشراء

1. يسجل العميل الدخول أو ينشئ حساباً.
2. يحمّل التطبيق الخدمات والمنتجات والأسعار وحقول المستفيد من API.
3. يختار العميل العملة المتاحة للمنتج ويدخل بيانات المستفيد.
4. يضبط PIN المعاملة من صفحة الحساب عند أول استخدام.
5. يرسل التطبيق المنتج والعملة والحقول ومفتاح Idempotency مع PIN في الترويسة.
6. يتحقق الخادم من توفر المنتج والسعر والحقول والرصيد وسياسات الطلب، ثم يسجل العملية عبر دورة الطلب والدفتر المالي.

لا توجد عمليات إيداع فوري من التطبيق ولا تعديل محلي للأرصدة. إيداع العميل عبر القنوات اليدوية يحتاج واجهة اختيار القناة وإرسال مرجع الحوالة وإثباتها؛ هذه الخطوة لم تُعرض في هذه النسخة لتجنب إيحاء أن الإيداع متاح قبل اكتمال مراجعة القنوات.

## حدود النسخة الحالية

- لم يتم تنفيذ تشغيل Flutter أو `flutter analyze` أو `flutter test` على جهاز تطوير Windows في هذه الجلسة. تمت إضافة اختبارات مساعدة إلى CI لتنفذها GitHub Actions.
- يلزم تنفيذ `flutter create --platforms=android,ios .` محلياً إذا لم توجد مجلدات المنصات الأصلية.
- لا يزال مطلوباً اختبار End-to-End مع حساب عميل حقيقي وبيانات كتالوج/أسعار في قاعدة بيانات Staging.
- تسجيل الدخول يعتمد على البريد أو الهاتف كما يفرض API. تسجيل الهاتف يحتاج إدخال الصيغة المقبولة من الخادم.
- التطبيق لا يتيح حتى الآن طلب الإيداع اليدوي أو عرض قنوات الدفع وسجل الإيداعات.
- لا تُعد هذه النسخة موافقة إطلاق إنتاجي.

## متغير API

يمكن تغيير العنوان من دون تعديل الكود:

```powershell
flutter run --dart-define=API_BASE_URL=https://api.example.com/api
```

لا تضع مفاتيح أو أسرار الخادم داخل `--dart-define`؛ عنوان API فقط.
