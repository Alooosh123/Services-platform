## 2. التعديلات في بنية البيانات وقاعدة البيانات (Schema & Database)

1. **نموذج طلبات الخدمات من العملاء (`ServiceRequest`):**
   - يدعم دورة حياة الطلب: `PENDING`, `IN_REVIEW`, `APPROVED`, `REJECTED`, `PUBLISHED`.
   - يخزن عنوان التطبيق، التصنيف، حقل المعرف المطلوب، الهاتف، والملاحظات الإدارية.
2. **نموذج إصدارات قواعد التسعير غير القابلة للتعديل (`PriceRuleVersion`):**
   - ترقيم النسخ (`version: 1, 2, ...`).
   - النطاق الهرمي (`PriceRuleScope`: `DEFAULT`, `CATEGORY`, `SERVICE`, `PRODUCT`).
   - نوع الهامش (`MarginType`: `PERCENTAGE`, `FIXED`).
   - سبب التعديل الإلزامي للرقابة (`changeReason`).
3. **توسيع نموذج المنتجات (`Product`):**
   - حقل `isManualFulfillment`: لتأكيد وضع التنفيذ اليدوي المرخص.
   - حقل `killSwitchReason`: لتوثيق سبب الإيقاف الطارئ.
4. **توسيع نموذج قنوات الدفع (`PaymentChannelConfig`):**
   - حقول الرقابة الثنائية: `financeApprovalRequired`, `pendingAccountNumber`, `pendingFeePercentage`.
   - حالة التحقق القانوني: `verificationStatus` (`VERIFIED`, `PENDING_REVIEW`, `REJECTED`).
   - حقل `killSwitchReason`: لتوثيق سبب تعطيل القناة.

## 3. الخدمات البرمجية والمحركات المنفذة (Backend Services)

1. **محرك التسعير الذكي (`PricingEngineService`):**
   - التحديد الهرمي للقواعد: `PRODUCT` &rarr; `SERVICE` &rarr; `CATEGORY` &rarr; `DEFAULT`.
   - احتساب التكلفة ورسوم البوابة (Gateway Fees) وتحويل العملات FX (USD, YER, SAR).
   - حظر البيع بخسارة وضمان هامش ربح موجب.
   - محاكاة فورية لحساب الأسعار (`calculatePrice`) قبل الاعتماد.
   - إصدار نسخ جديدة مرقمة مع أرشفة النسخ السابقة.
2. **خدمة الكتالوج وبوابة المزودين (`ProductsService`):**
   - فحص بوابة المزود (`Provider Mapping Gating`) في `createProduct` و`updateProduct`.
   - زر الإيقاف الطارئ للباقات (`toggleProductKillSwitch`).
   - دورة حياة طلبات الخدمات ونشرها في الكتالوج بنقرة زر واحدة (`Zero-Code Dynamic Publishing`).
3. **محولات قنوات الدفع والرقابة الثنائية (`BasePaymentChannelAdapter` & `DepositsService`):**
   - طريقة `proposeAccountChange` التي تعلق الحساب الجديد في حالة `PENDING_REVIEW`.
   - طريقة `approveFinanceReview` التي تتطلب اعتماد ضابط الإدارة المالية لتفعيل الرقم الجديد.
   - زر الإيقاف الطارئ للقنوات (`triggerKillSwitch`).

## 4. الواجهات التفاعلية (Web Applications UI)

### 4.1 لوحة تحكم الإدارة (Web Admin - Port 3001)
- **صفحة المنتجات والتسعير (`/products`):**
  - **تبويب الكتالوج:** بطاقات الألعاب مع حقول الإدخال النمطية (Regex)، بطاقات الباقات مع مؤشر بوابة المزود (`Provider Gated` vs `Manual Mode`)، وزر الإيقاف الطارئ (`Power` icon).
  - **تبويب محرك التسعير الذكي:** محاكي التسعير الفوري التفاعلي (Live Simulator)، وجدول قواعد التسعير النشطة مع رقم الإصدار وسجل التدقيق.
  - **تبويب طلبات العملاء:** مراجعة طلبات المستخدمين المنشأة من المتجر وزر "اعتماد ونشر في الكتالوج فوراً".
- **صفحة الإيداعات والقنوات (`/deposits`):**
  - **تبويب قنوات الدفع والاعتماد المالي المزدوج:** عرض القنوات اليمنية، اقتراح تعديل رقم الحساب، أزرار اعتماد أو رفض الإدارة المالية (Four-Eyes Dual Approval)، وزر الإيقاف الطارئ للقناة.

### 4.2 متجر العملاء (Web Customer Store - Port 3000)
- **الصفحة الرئيسية (`/`):**
  - بانر تفاعلي راقٍ: "لم تجد لعبتك أو تطبيقك المفضل في المتجر؟ اطلب توفير لعبة أو تطبيق جديد فوراً!".
  - نافذة منبثقة لتقديم طلب الخدمة وحقل الشحن ورقم الهاتف.
- **صفحة الشحن (`/topup/[slug]`):**
  - كشف الباقات المتوقفة بزر الطوارئ وعرض شارة "⚠️ متوقفة مؤقتاً (صيانة)" مع تعطيل اختيارها وحظر تنفيذ طلب الشحن عليها لمنع الخسائر.

## 6. دليل الفحص والتجربة اليدوية للمستخدم (Manual Verification Guide)

الخوادم تعمل كـ Background Daemons على الأجهزة المحلية:
- **المتجر المخصص للعميل (Customer Store):** [http://localhost:3000](http://localhost:3000)
- **لوحة الإدارة المالية والتشغيلية (Web Admin):** [http://localhost:3001](http://localhost:3001)
- **واجهة الـ Backend API التفاعلية (Swagger):** [http://localhost:4000/api/docs](http://localhost:4000/api/docs)

### سيناريوهات التحقق المقترحة:
1. **فحص طلب خدمة جديدة ونشرها:**
   - افتح [http://localhost:3000](http://localhost:3000) وانزل لأسفل الصفحة واضغط "اطلب إضافة لعبة أو تطبيق جديد".
   - أرسل طلباً لتطبيق جديد (مثلاً: لايكي أو كول أوف ديوتي).
   - افتح [http://localhost:3001/products](http://localhost:3001/products) وتوجه لتبويب "طلبات العملاء للتطبيقات الجديدة" واضغط "اعتماد ونشر في الكتالوج فوراً".
2. **فحص محاكي التسعير الفوري:**
   - في [http://localhost:3001/products](http://localhost:3001/products)، توجه لتبويب "محرك الهوامش والتسعير الذكي".
   - أدخل سعر التكلفة من المزود $4.50 واختر العملة المستهدفة واضغط "احسب السعر الفوري" لرؤية تفاصيل الرسوم وسعر البيع المقترح وهامش الربح.
3. **فحص الرقابة الثنائية لقنوات الدفع (Four-Eyes Principle):**
   - افتح [http://localhost:3001/deposits](http://localhost:3001/deposits) واختر تبويب "قنوات الدفع والاعتماد المالي المزدوج".
   - اضغط "تعديل رقم الحساب المستلم" لأي قناة وأدخل رقماً جديداً.
   - ستظهر القناة بحالة "بانتظار موافقة المالية" وتظهر أزرار "موافقة واعتماد المالية" أو "رفض التعديل".
4. **فحص زر الإيقاف الطارئ (Emergency Kill Switch):**
   - في [http://localhost:3001/products](http://localhost:3001/products)، اضغط زر الطاقة الأحمر بجانب باقة معينة لإيقافها.
   - انتقل لمتجر العميل [http://localhost:3000/topup/pubg-mobile](http://localhost:3000/topup/pubg-mobile) وتأكد من أن الباقة أصبحت متوقفة ومعطلة لحماية الرصيد.
