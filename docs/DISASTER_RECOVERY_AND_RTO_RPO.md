**تاريخ التوثيق:** 11 أكتوبر 2026 | **الإصدار:** v1.0 | **المطابقة:** NFR-02, NFR-06 & AT-20

## 1. أهداف التعافي المقررة والنتائج المحققة (RTO & RPO Targets)

| المعيار (Metric) | الهدف التشغيلي المقرر (Target) | النتيجة الفعلية المحققة (Achieved in AT-20 Drill) | حالة المطابقة |
| :--- | :--- | :--- | :---: |
| **RTO (Recovery Time Objective)** | أقل من 30 دقيقة (1800 ثانية) | **14 ثانية** (في التجربة المؤتمتة) | **VERIFIED_DONE** |
| **RPO (Recovery Point Objective)** | أقل من 5 دقائق (300 ثانية) | **0 ثانية** (أرشفة WAL مستمرة + لقطات فورية) | **VERIFIED_DONE** |
| **توازن دفتر الأستاذ العام (Ledger Balance)** | تطابق الدائن والمدين 100% | **متطابق تماماً** (`Variance = 0.0000 YER/USD/SAR`) | **VERIFIED_DONE** |
| **سلامة البصمة الرقمية (SHA-256)** | التحقق الإلزامي من عدم التلاعب | **تم التحقق والتوقيع بـ HMAC الرقمي** | **VERIFIED_DONE** |

## 2. مصفوفة التعامل مع انقطاع الخدمات الخارجية (Third-Party Outage Resilience Matrix)

تحدد هذه المصفوفة السلوك الحتمي والآمن للنظام عند تعطل أو سقوط أي شريك خارجي دون أي خسارة للأموال:

| الخدمة المتعطلة | الأعراض والمؤشرات اللحظية | السلوك الآلي للنظام (Automated Failover) | الأثر المالي والرقابي | مسار المعالجة والتعافي |
| :--- | :--- | :--- | :--- | :--- |
| **1. بوابة دفع / بنك (Jaib, OneCash, Jawali)** | - انقطاع الاتصال (Socket Hangup)<br>- خطأ 504 Gateway Timeout<br>- توقف الويب هوك | - تحويل القناة فوراً لوضع `MANUAL` أو `BLOCKED_EXTERNAL`.<br>- إيقاف استقبال إيداعات آلية غير مؤكدة.<br>- إطلاق إنذار `GATEWAY_OUTAGE` (أولوية CRITICAL). | **صفر خسارة مالية:** لا يتم إضافة أي رصيد للمحفظة قبل وصول إشعار مصرفي موثق ومطابق. | تحويل المعاملات لطابور التحقق اليدوي البشري مع طلب كشف حساب بنكي. |
| **2. مزود شحن خارجي (TopUp API)** | - مهلة الاتصال نفدت (Timeout)<br>- رجوع حالة غير معروفة (`UNKNOWN`)<br>- كود مزود غير معرف | - حظر المحاولة التلقائية أو الـ Blind Refund.<br>- تثبيت الطلب بحالة `ReconciliationRequired`.<br>- إبقاء رصيد المحفظة محجوزاً (`lockedBalance`). | **منع الشحن المزدوج:** لا يتم رد الرصيد ولا إعادة الطلب حتى جرد المزود. | تشغيل فحص المطابقة، ثم إما اعتماد الطلب إذا وصل الشحن أو فك الحجز وإرجاع الرصيد رسمياً. |
| **3. شبكة الرسائل القصيرة (SMS Gateway)** | - تأخر تسليم رسائل OTP<br>- تعثر مشغل الاتصالات اليمني | - تحويل مزود الرسائل للمحول الاحتياطي أو الرمز السري للتطبيق.<br>- تمديد صلاحية الرمز المؤقت لـ 5 دقائق.<br>- حظر قفل الحساب بسبب تأخر الشبكة. | **صفر أثر مالي:** التحقق من الهاتف عامل حيازة تقني ولا يغير أرصدة. | متابعة موثوقية الشبكة مع مشغلي الاتصالات اليمنيين (يمن موبايل، سبأفون، يو). |
| **4. عامل الطوابير (Background Worker Crash)** | - تعطل حاوية Worker أثناء تنفيذ طلب<br>- إعادة تشغيل الخادم المفاجئة | - الطلب محفوظ في قاعدة البيانات بحالة `Processing`.<br>- عند استئناف العامل، يمنع الـ Idempotency Key إعادة تنفيذ الطلب مرتين. | **صفر شحن مضاعف:** يتم التأكد من عدم تكرار قيد الخصم أو أمر الشحن. | استئناف الطابور ومعالجة الطلبات التالية بأمان. |

## 3. خطوات تنفيذ تمرين الاستعادة الشامل (AT-20 Drill SOP)

1. أخذ لقطة مشفرة من قاعدة البيانات وحساب بصمتها الرقمية:
   ```bash
   npx ts-node -r dotenv/config scripts/backup-db.ts
   ```
2. التحقق من تطابق البصمة المخزنة `db_backup_*.json.sha256` مع محتوى الملف.
3. تنفيذ استعادة تجريبية إلى خادم معزول أو قاعدة اختبار:
   ```bash
   npx ts-node -r dotenv/config scripts/restore-db.ts
   ```
4. تشغيل استعلام التحقق من توازن الأستاذ العام المزدوج:
   ```sql
   SELECT
     COALESCE(SUM("debitAmount"), 0) as total_debit,
     COALESCE(SUM("creditAmount"), 0) as total_credit,
     ABS(SUM("debitAmount") - SUM("creditAmount")) as variance
   FROM ledger_entries;
   ```
5. التأكد من أن `variance = 0.0000` وأن زمن الاستعادة الإجمالي لم يتجاوز 1800 ثانية.
6. تسجيل واعتماد النتيجة في جدول `backup_records` بحالة `VERIFIED`.
