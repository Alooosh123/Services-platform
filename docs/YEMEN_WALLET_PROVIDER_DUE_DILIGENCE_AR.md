# التحقق الرسمي من قنوات الدفع اليمنية وملف طلب التكامل

**تاريخ التحقق:** 9 نوفمبر 2026  
**النطاق:** قنوات استقبال مدفوعات العملاء في منصة الشحن والخدمات الرقمية  
**الحالة:** بحث مكتبي من المصادر العامة؛ لم يتم تسجيل حساب تاجر أو إجراء اتصال خاص أو اختبار Sandbox حي.

> هذه الوثيقة تصحح أي افتراض سابق بأن جميع المحافظ توفر API عاماً أو أن مجرد وجود تطبيق/محفظة يعني جواز استخدامها تجارياً. لا تُفعّل أي قناة في الإنتاج قبل التحقق التنظيمي والتعاقدي والتقني.

## 1. نتيجة التحقق التنظيمي

نشر البنك المركزي اليمني – المركز الرئيسي عدن التعميم رقم **CBY/L/282/2024** بتاريخ 26 يونيو 2024 بشأن حظر التعامل مع كيانات ومحافظ وخدمات دفع إلكتروني غير مرخصة، وتضمنت قائمته: كاش، جوالي، جيب Jaib، وي كاش، وغيرها. صفحة الرقابة الرسمية ما زالت تعرض رابط التعميم، كما تعرض قرار المحافظ رقم 4 لسنة 2025 المعدل لبعض أحكام الدفع الإلكتروني وقائمة البنوك المرخصة وقائمة شركات الصرافة ووكلاء الحوالات المرخصين لعام 2026.

**لا نستنتج من نتائج البحث وحدها أن كل جهة في تعميم 2024 ما زالت غير مرخصة اليوم، ولا أن قرار 2025 منحها ترخيصاً.** يجب طلب إفادة خطية حديثة من البنك المركزي/الجهة الرقابية المختصة، والتحقق من اسم الكيان القانوني ورقم الترخيص ونطاقه وتاريخ سريانه قبل التعاقد أو استقبال أموال العملاء.

## 3. وسطاء التحقق من إشعارات الدفع

### Esaalat
الموقع https://esaalat.com/en يعلن خدمة تحقق تقرأ إشعار SMS الوارد إلى هاتف التاجر، وتطابق بيانات التحويل، ثم ترسل Webhook/API. يعلن دعم Kuraimi وJaib وJawali وFloosak وOneCash، ويصرح صراحة بأنه **غير تابع لمزودي المحافظ المعروضين**.

هذا ليس API رسمياً صادراً عن المحافظ، ولا يثبت أن Esaalat مخول قانونياً لاستقبال أو حفظ أموال العملاء أو إصدار أوامر دفع/سحب. هو طبقة تحقق من إشعارات واردة وفق وصفه العام. قبل اعتماده:
1. احصل على عقد تاجر واتفاقية معالجة بيانات وبيان المسؤوليات.
2. تحقق من الوضع القانوني والترخيص/الموافقات المطلوبة من البنك المركزي.
3. اطلب دليل API الكامل، توثيق Webhook وتوقيعه، آلية منع إعادة الإرسال، SLA، وسياسة الاحتفاظ بالبيانات.
4. اختبر حالات الإشعار المكرر، المبلغ الخاطئ، العملة الخاطئة، التحويل إلى محفظة مختلفة، تأخر SMS، انقطاع الهاتف، وتزوير/إعادة تشغيل Webhook.
5. لا تعتمد Screenshot أو SMS وحده كدليل مالي نهائي إذا لم توجد آلية تحقق موثوقة ومستقلة ومسموح بها تعاقدياً وتنظيمياً.

روابط:
- https://esaalat.com/en
- https://esaalat.com/en/sdk

### YemenPay
الموقع https://yemenpay.app يعلن بوابة دفع للمحافظ وSDK وSandbox. صفحة SDK العامة تعرض وضع Playground، وتتضمن رقم اختبار 771234567 لمحاكاة النجاح وأرقاماً أخرى للفشل. هذه محاكاة للواجهة وليست دليلاً على معاملة مالية أو على اعتماد قانوني/تنظيمي أو على أن Sandbox متصل بمحافظ حقيقية. لم يتم التحقق من الترخيص أو العلاقة التعاقدية مع كل محفظة.

قبل أي اعتماد: اطلب الاسم القانوني، الترخيص أو أساس الإعفاء/الموافقة، قائمة المحافظ المتعاقد معها، عقد التاجر، وثائق API، بيئة Sandbox خادمية حقيقية، مفاتيح اختبار، توقيع Webhook، التسوية والاسترداد، والرسوم. لا تضعه في الإنتاج اعتماداً على صفحة العرض وحدها.
- https://yemenpay.app/
- https://yemenpay.app/sdk-doc
- https://yemenpay.app/faq

## 4. ملف الوثائق الذي يجب طلبه من كل محفظة أو بوابة

اطلب الحزمة التالية بصيغة PDF/بوابة مطورين رسمية، مع تأكيد مكتوب أنها تخص كيانك التجاري:

1. **ملف التاجر والامتثال:** الاسم القانوني، السجل التجاري، الترخيص/الموافقة التنظيمية ذات الصلة، نطاق النشاط، الدول/المناطق والعملات، KYC/KYB، AML/CFT، شروط قبول نشاط الشحن الرقمي.
2. **اتفاقية التاجر:** عمولة المعاملات، رسوم التسوية، حدود العمليات، الاحتياطي/الحجز، مواعيد التسوية، الاسترداد والنزاعات، الإيقاف والإنهاء، المسؤولية والتعويض، SLA والدعم.
3. **API Specification:** Base URLs منفصلة لـ Sandbox وProduction، OpenAPI/Swagger أو Postman collection، HTTP methods، schemas، field constraints، error codes، rate limits، pagination، idempotency.
4. **المصادقة والأمن:** آلية OAuth2/API key/mTLS أو التوقيع، canonical string، خوارزمية التوقيع، تدوير المفاتيح، IP allowlist، شهادات TLS، انتهاء الصلاحية، وإبطال المفاتيح.
5. **عمليات الدفع:** إنشاء جلسة/طلب دفع، الاستعلام عن الحالة، تأكيد server-to-server، إلغاء، refund كامل/جزئي، كشف حساب، reconciliation، وعمليات payout إن كانت متاحة ومصرحاً بها.
6. **Webhooks:** أحداث الدفع، التوقيع والتحقق، timestamps/nonces، retry policy، ترتيب الأحداث، تكرار الحدث، واختبار endpoint.
7. **Sandbox Kit:** حساب تاجر تجريبي، بيانات/محافظ اختبار، مفاتيح Sandbox، مبالغ وحالات اختبار، محاكاة timeout/decline/reversal/refund، ودليل قبول الاختبار.
8. **التشغيل:** Production credentials تصدر بعد الاعتماد، عناوين IP، نطاقات callbacks، جهة اتصال تقنية/مالية للطوارئ، status page، وجدول الصيانة.
9. **التسوية المالية:** صيغة كشف الحساب، transaction/reference IDs، الرسوم، صافي التسوية، عملة التسوية، وقت القطع، فروقات التوقيت، وآلية الاعتراض.
10. **التوقيع والاعتماد:** خطاب يحدد أن الحساب/المحفظة باسم الكيان التجاري، وأن استخدام API أو وكيل التحصيل مسموح لنشاط المنصة.

لا ترسل أسرار Sandbox أو Production إلى GitHub أو المحادثات. خزّنها في Secret Manager/متغيرات بيئة السيرفر بعد إصدارها.

## 5. إذا لم توجد API رسمية: مسار الوكيل

يمكن استخدام وكيل/موظف تنفيذ فقط بعد إثبات أن الترتيب مسموح به من مزود المحفظة والجهة الرقابية، وأن الوكيل معتمد/متعاقد، وأن الحساب المستخدم مخصص لنشاط تجاري مسموح. لا تستخدم حسابات شخصية أو تشارك PIN/OTP أو كلمات المرور أو تتجاوز ضوابط المحفظة.

التدفق المقترح داخل المنصة:
1. ينشئ النظام طلب دفع فريداً بحالة PENDING.
2. يعرض بيانات التحويل المعتمدة الصادرة عن المزود/الوكيل، مع المبلغ والعملة والمرجع.
3. لا يثق النظام بصورة الإيصال أو إدخال العميل كإثبات نهائي.
4. يراجع الوكيل كشف المعاملات داخل التطبيق/القناة الرسمية، ويتحقق من رقم العملية والمبلغ والعملة والوقت والحساب المستفيد.
5. يسجل الوكيل نتيجة التحقق مع مرجع المصدر ودليل المراجعة، دون حفظ PIN/OTP أو بيانات اعتماد المحفظة.
6. يراجع موظف مالية ثانٍ الحالات عالية القيمة أو الاستثناءات وفق حدود موافقات موثقة.
7. بعد التحقق فقط، تنفذ المنصة قيداً مزدوجاً ذرياً، بمفتاح idempotency فريد. إذا تعذر التحقق تبقى الحالة PENDING/REVIEW ولا يضاف رصيد.
8. تُجرى مطابقة يومية بين سجلات المنصة وكشف المحفظة، مع آلية اعتراض وتسوية.

## 6. قرار التفعيل الحالي

جميع القنوات المحلية المذكورة تظل معطلة افتراضياً في الإنتاج حتى استكمال:
- التحقق التنظيمي الحديث من الكيان القانوني والترخيص ونطاقه.
- عقد التاجر أو الوكيل المكتوب.
- وثائق API/Sandbox أو اعتماد مسار الوكيل.
- إثبات ملكية حساب الاستقبال التجاري.
- نجاح اختبارات الدفع والإشعارات والتسوية والاسترداد والمطابقة.

**لا يتم إدخال أرقام حسابات استقبال أو مفاتيح أو أسماء وكلاء تجريبية.** استخدم سجلات إعدادات غير نشطة فقط، ولا تعرض خيار الدفع للعميل حتى يصبح التفعيل معتمداً.
