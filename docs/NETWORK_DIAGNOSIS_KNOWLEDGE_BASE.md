# قاعدة معرفة تشخيص الشبكة — MikroTik RouterOS

**الحالة:** مرجع تشغيلي أولي للقراءة فقط. لا تعتبره محرك إصلاح تلقائي أو بديلاً عن مهندس الشبكات.

## منهجية المصدر

تعتمد التوصيات على وثائق MikroTik الرسمية المشار إليها أدناه، بينما عتبات تصنيف CPU والذاكرة في المنصة حدود تشغيلية داخلية قابلة للضبط وليست عتبات رسمية موصى بها من MikroTik. سجلات الجهاز وبيانات الموقع وطوبولوجيا الشبكة الفعلية هي التي تحسم السبب.

## قواعد التشخيص

| Rule ID | إشارة الرصد | التفسير الآمن | الفحوص المقترحة |
|---|---|---|---|
| NET-CPU-01 | CPU من 85% إلى أقل من 95% | تحذير داخلي؛ قد يكون مؤقتاً أو حملاً عادياً | قارن عدة عينات ووقت الذروة والخدمات والمهام المجدولة، وافحص سجلات النظام |
| NET-CPU-02 | CPU 95% أو أكثر | تنبيه حرج داخلي؛ لا يحدد وحده العملية المسببة | احفظ عينة الموارد والسجلات، راجع الواجهات عالية المرور، ولا توقف خدمة أو تعِد التشغيل آلياً |
| NET-MEM-01 | الذاكرة الحرة أقل من 15% | تنبيه داخلي يحتاج متابعة اتجاه | قارن عدة عينات، راجع العمليات والخدمات المفعّلة وتغييرات الإعداد الأخيرة |
| NET-MEM-02 | الذاكرة الحرة أقل من 5% | حرج داخلي | احفظ السجلات، افحص الميزات/الخدمات التي تستهلك الذاكرة، صعّد لمهندس الشبكات ولا تحذف إعدادات تلقائياً |
| NET-IF-01 | الواجهة غير معطلة لكنها ليست running | قد يكون كابل/طاقة/طرف مقابل/تفاوض سرعة أو مشكلة إعداد | افحص الكابل والطرف المقابل وحالة المنفذ والتفاوض؛ لا تفعّل الواجهة تلقائياً |
| NET-TLS-01 | فشل TLS أو CA | لا يمكن الوثوق بقناة الإدارة | تحقق من www-ssl والشهادة واسم المضيف وسلسلة CA؛ لا تتجاوز التحقق ولا تستخدم HTTP |
| NET-AUTH-01 | HTTP 401/403 | حساب المراقبة أو صلاحيات REST غير صحيحة | تحقق من الحساب المخصص وسياسة read/rest-api؛ لا تستخدم admin ولا تمنحه write |
| NET-REST-01 | رد REST غير صالح أو redirect | عنوان/إصدار/مسار REST غير متوافق أو proxy غير صحيح | تحقق من URL النهائي ومسار `/rest` وإصدار RouterOS؛ لا تتبع redirect الحامل لبيانات Basic Auth |

## القيود

- وكيل المنصة يقرأ فقط `GET /rest/system/identity`, `GET /rest/system/resource`, `GET /rest/interface`.
- عنوان الراوتر يجب أن يكون IPv4 خاصاً في شبكة الإدارة، والاتصال HTTPS مع شهادة موثوقة.
- لا توجد أوامر POST/PUT/PATCH/DELETE ولا أوامر CLI في عميل الوكيل.
- لا ينفذ الوكيل reboot أو enable/disable interface أو firewall/routing/QoS changes أو تغيير credentials.
- لا توجد مراقبة traffic counters أو SNMP حالياً؛ يمكن إضافتها بعد مراجعة حدود القراءة والصلاحيات.
- الحالة HEALTHY تعني عدم تطابق القواعد الحالية فقط، ولا تعني أن الشبكة خالية من الأعطال.
